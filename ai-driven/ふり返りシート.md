# ふり返りシート（かんたん版）

AI に頼む前に ①②③、作った後に ④⑤ を書きます。1 ステップ 5 行だけです。
② の中身は `00_決定ログ.md` に書き、ここには番号（D-000 など）だけ書けば十分です。

---

## ステップ 1: 要件定義

| 項目 | 記入 |
|---|---|
| ① ゴール（1 文） |要求一覧に書いてあることだけを、番号付きの要件にする|
| ② 自分で決めること（最大 3 つ） | D-000〜D-007（D-005、D-006 は見直して変更） |
| ③ OK の条件（最大 3 つ） |1. すべての要件に、要求一覧の項番（出所）が付いている　2. 要求一覧に書いていない機能が 1 つも入っていない　3. 決められなかったことは「確認事項」として並んでいる|
| ④ 確かめた結果（✔ / ✖） | 条件1 ✔　条件2 ✔　条件3 ✔（FR-05-7、FR-03-5、FR-02-5 を要求一覧と見比べた） |

⑤ ふり返り

```
AI に任せたこと : 要件定義書の本文と対応表を書くこと。別の AI に採点者役で照合させること
自分が決めたこと: 要求にないものは作らない。会員IDの時期、さかのぼり値引き、同一商品の数量加算、カメラ、ボタン任意、読み込みと追加の 2 操作で追加、画面イメージは参考
次に気をつけること: 決めずに空けた所は AI が仮に埋める。先に「決めること」を書いてから頼む。理由も自分で書く
```

## ステップ 2: 設計

| 項目 | 記入 |
|---|---|
| ① ゴール（1 文） | 要件定義書 v2 の 70 件を、画面・API・データベースの形にする |
| ② 自分で決めること（最大 3 つ） | D-008（金額計算はサーバ側）、D-009（「今日」はサーバが日本時間で作る）、D-010（課題の指定項目も設計の根拠にする）。要求にない値は仮の値 ★ として K 番号と結びつける（D-000） |
| ③ OK の条件（最大 3 つ） | 1. すべての API に入力・出力・エラーが書いてある　2. 日付・時刻・端数・上限の決め方が、すべて「どこで・いつ」まで書いてある　3. 仮の値 ★ が全部 K 番号と結びついている |
| ④ 確かめた結果（✔ / ✖） | 確かめ1 ✔（取引日はサーバが UTC を日本時間に直して作る）　確かめ2 ✔（★ と K の結びつきを見比べた） |

⑤ ふり返り

```
AI に任せたこと : 設計書の本文と図、別 AI による 2 回の照合
自分が決めたこと: 金額計算はサーバ、「今日」はサーバが日本時間で作る、課題の指定項目も根拠にする
次に気をつけること: 設計を進めると要求にない値が増える。そのたびに K を足して結び直す。AI は最初、無関係な K にまとめて結んでいた
```
