## 決めなければ次に進めない論点

「候補」は AI が要求一覧から洗い出したもの。**採用する行を人が選び、不要な行は消す**。足りない論点は人が追加する。

| # | 論点 | なぜ決める必要があるか | 決めないとどう埋まるか（AI の既成概念） | 採用 |
|---|---|---|---|---|
| 候補 1 | 同一商品を再登録したとき、行を増やすか数量を増やすか | Lv1 2.3「1商品1行」と Lv2 2.1「数量を増やす」が矛盾 | 新しい方（Lv2）が採られるが、根拠が書かれない | |
| 候補 2 | 会員IDを読み込める時期 | Lv1 2.6「買い物前」と Lv2 2.8「いつでも」が矛盾 | 「いつでも」になるが、先に登録した商品への値引きの扱いが曖昧になる | |
| 候補 3 | Lv2 前提条件「Lv3 でカメラ」と Lv2 2.1 のカメラ要求の関係 | Lv2 で作るのか Lv3 なのかで実装範囲が変わる | 「作る」と解釈されるが、出題者への確認事項にならない | |
| 候補 4 | 「レジ担当者の情報」の中身 | 画面に何を出すかが決まらない | 氏名・ID・所属など複数が表示される | |
| 候補 5 | 「お客様ID読み込みボタン」の役割 | 会員なしで進む操作をどうするか | 「読み込み」と「会員なしで進む」が別ボタンになる | |
| 候補 6 | 要求にない機能を要件にするか（ログアウト、管理画面、権限、決済方法、会計キャンセル、返品、レシート） | スコープの線引き | 一般的な POS の機能として追加される（1 回目の指摘） | |
| 候補 7 | 決めないと動かないが要求にない事項の扱い（数量 99 超、空リストで購入、端数処理、値引きの重複、存在しない会員の後の操作、パスワードの保持方法、バーコードの規格） | 実装時に必ず必要になる | AI が「普通は切り捨て」「普通はエラー」で埋める | |
| 候補 8 | 「購入結果を保存」で何を保存するか（いつ・何を・いくつ・いくらで・誰が買い・誰が処理したか） | データ項目が決まらない | 一般的な取引テーブルの列が足される | |
| 候補 9 | 「消費税率をプログラムを直さずに変えられる」の手段（設定ファイル／DB／管理画面） | FR の粒度と、管理画面を作るかどうかに直結 | 管理画面が要件に入る | |
