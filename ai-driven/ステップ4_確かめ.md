## OK の条件 2: 自分で読んだ場所が設計どおり（DB につなぐ所）

読むファイル: `pos-app/backend/app/db.py`（約 90 行）。見るのは次の 3 か所だけで十分です。

| 見る所 | 何が書いてあればよいか | なぜ大事か |
|---|---|---|
| 1. `build_database_url` という関数（30 行目あたり） | `URL.create(...)` に `password=settings.db_password` と、パスワードを**そのまま渡している**こと。`f"...{password}@{host}..."` のような、文字列へのはめ込みが**ない**こと | 今回のパスワードには `@` と `&` が入っている。はめ込むと `@` が区切りと解釈されて接続に失敗する。これが「パスワードの罠」 |
| 2. `make_engine` の中の `ssl.create_default_context`（60 行目あたり） | MySQL につなぐときは必ず `"ssl": context` を渡していること | Azure の MySQL は暗号化通信が必須。証明書の検証もここで有効になる |
| 3. `pool_size`、`pool_recycle` と、`SET time_zone = '+00:00'`（59 行目、70 行目あたり） | 接続を使い回す設定があること。接続のたびに時間帯を UTC に固定していること | 要件 N-06（接続を維持する）と、設計の「日時は UTC で保存する」 |

教材の書き方との違いは、次のテストでも確かめています（`pos-app/backend/tests/test_db_url.py`）。

- `@ & : / #` を含む作り物のパスワードを渡しても、ユーザー名・ホスト名・パスワードがずれない
- 文字列に直したときは、記号が `%40` や `%26` に変換されている
- 画面やログに出すときは、パスワードが隠れる

**AI の見立て**: 設計どおり。別の AI の照合でも「はめ込みなし、記号で壊れない、パスワードは表示されない」と確認された。
**あなたが見る所**: 上の表の 1。関数の中に `@` をはさむ f 文字列がないこと。

## 別の AI の照合で直したこと

設計に大きく反する混入（ログアウト、管理画面、現金決済、氏名の表示など）は「なし」でした。直したのは次の点です。

| 指摘 | 直した内容 |
|---|---|
| **不具合**: 数量を変えた直後、金額の計算し直しが届く前に購入を押すと、古い内容で保存される | 計算し直しが届くまで購入ボタンを押せないようにした。テストを追加 |
| 画面側に、税を計算する関数が残っていた（1 回目の残り。金額計算はサーバだけ、という D-008 に反する） | 関数とそのテストを削除。小計も、サーバの結果が届くまでは「—」を出す |
| 設定を忘れると Swagger（API の説明ページ）が公開される | 既定を本番扱いに変更。開発のときだけ `.env` で指定する |
| ログイン用の鍵（JWT_SECRET）に、公開された既定値があった | 既定値をなくし、32 文字未満なら起動時にエラーにした |
| 証明書ファイルを指定したとき、サーバの証明書を検証しない可能性 | どちらの場合も検証する形に統一 |
| パスワード登録時の 8〜64 文字の検査がなかった | `hash_password` に検査を追加。入力はコマンドの履歴に残らない形に |
| 初期データの担当者のパスワードが公開されている | 手元でない DB には、明示しない限り入れないようにした。README に注意書き |
| README が 1 回目のまま（やめた書き方で DB 接続を案内していた） | v2 の内容に書き直した |
| テーブル定義の SQL が、データベース名を `pos` に固定していた | 固定をやめ、使うデータベースを選んでから実行する形に |
